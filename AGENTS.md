# Правила работы над Memly

- Перед реализацией читать `docs/development-plan.md`, `docs/architecture.md` и `docs/code-style.md`.
- Соблюдать текущую задачу и этап разработки. Не добавлять функции последующих этапов без запроса.
- Использовать TypeScript со строгой проверкой типов при появлении прикладного кода.
- Отступ — два пробела. Форматировать код единообразно по `.editorconfig` и `.prettierrc.json`.
- Не смешивать HTTP, бизнес-правила, SQL и UI в одном модуле. Не передавать клиенту внутренние модели БД.
- Проверять права доступа на сервере для HTTP-запросов, фоновых задач и Socket.IO-событий.
- Изменения БД сопровождать проверяемыми миграциями; не использовать schema push в production.
- Не коммитить секреты, пользовательские файлы и дампы баз данных.
- Для функциональных изменений выполнять подходящие проверки типов, форматирования и тесты поведения.
- Не выдавать документационные заготовки за работающие приложения. Указывать фактический статус.
- При изменении архитектурного решения обновлять соответствующий ADR и документацию.
