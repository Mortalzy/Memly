# Запуск Memly с Windows 11 через ngrok

React-сборку и `/api` обслуживает один Express на `127.0.0.1:3001`.
ngrok публикует этот порт по HTTPS. PostgreSQL остаётся локальной.
Компьютер, PostgreSQL, приложение и туннель должны работать; сон Windows отключите
на время использования. Это первый ручной запуск, без автоматического старта Windows.

## Подготовка

Нужны уже установленные Node.js 24, npm 11, PostgreSQL и ngrok.
В PowerShell выполните `ngrok version`. В кабинете ngrok скопируйте команду
`ngrok config add-authtoken ...` и выполните локально. Токен в проект не записывается.

Остановите `npm run dev` через Ctrl+C. Сохраните копию базы перед обновлением:
`npm run db:backup` (см. ниже). Из корня Memly:

```powershell
git pull --ff-only
npm ci
npm run db:generate
npm run db:migrate
npm run build
```

`db:migrate` применяет миграции без сброса базы. Не используйте `migrate reset`.
В `.env` сохраните свою `DATABASE_URL` и сильный `BETTER_AUTH_SECRET`.
Пароли, которые оказались в переписке, замените, включая пароль приложения почты.
Смена `BETTER_AUTH_SECRET` потребует заново войти в аккаунты.

Измените настройки (адрес должен совпадать с выданным в кабинете ngrok):

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3001
BETTER_AUTH_URL=https://various-blame-compel.ngrok-free.dev
TRUSTED_ORIGINS=https://various-blame-compel.ngrok-free.dev
TRUST_PROXY=0
SMTP_HOST=smtp.mail.ru
SMTP_PORT=587
SMTP_USER=ВАШ_EMAIL
SMTP_PASSWORD=НОВЫЙ_ПАРОЛЬ_ПРИЛОЖЕНИЯ
SMTP_FROM=ВАШ_EMAIL
```

Оба email должны быть вашим адресом отправителя; вместо обычного пароля используйте
пароль приложения почтового сервиса. На 587 в production требуется STARTTLS.
Не копируйте демонстрационные значения поверх действующей строки подключения к БД.
Не включайте VITE_DEMO_MODE: интерфейс должен использовать настоящий API.

`TRUST_PROXY=0` намеренно не доверяет forwarded-заголовкам туннеля: общий лимит
API при таком первом запуске применяется ко всем посетителям вместе. Для двух
пользователей это простой вариант; поддержку индивидуального IP можно настроить
отдельно после проверки цепочки прокси. Открывать порты роутера не требуется.

## Запуск

Первый терминал, из корня Memly:

```powershell
npm start
```

Второй терминал, тоже из корня Memly:

```powershell
npm run tunnel
```

Туннель использует адрес `BETTER_AUTH_URL` и порт `PORT` из `.env`.
Если ngrok сообщает об отсутствии авторизации, выполните команду добавления
токена из своего кабинета. Не присылайте токен, `.env` или SMTP-пароль в чат.

Проверка в третьем терминале:

```powershell
Invoke-RestMethod http://127.0.0.1:3001/api/ready
```

Должен вернуться `status: ok`. Откройте публичный адрес с телефона через мобильный
интернет. На бесплатном ngrok может появиться промежуточная страница — нажмите Visit.
Войдите в свой аккаунт. Проверьте получение письма подтверждения (включая спам).
Создайте отдельный аккаунт девушки, добавьте набор, завершите занятие и убедитесь,
что набор и прогресс видны после повторного входа и с другого устройства.
Проверьте озвучку на её устройстве: доступные голоса определяет браузер/система.

Ссылку для подтверждения email открывайте через публичный адрес, не localhost:
в production используются Secure-cookie. Для использования со своего компьютера
также открывайте публичный адрес. При смене адреса обновите обе переменные и
перезапустите сервер и туннель. Закрытие терминала или Ctrl+C останавливает процесс.

## Резервные копии

Если `pg_dump` отсутствует в PATH, добавьте в `.env` полный путь к установленному
исполняемому файлу, например для PostgreSQL 18:

```dotenv
PG_DUMP_PATH="C:\Program Files\PostgreSQL\18\bin\pg_dump.exe"
```

Из корня проекта:

```powershell
npm run db:backup
```

Команда создаёт датированный `.dump` в `backups/`; пароль не передаётся в аргументах
процесса и не печатается. `.env` и `backups/` исключены из git. Создавайте копии перед
обновлениями и регулярно во время использования; переносите их на другой носитель.
Одна копия на том же диске не защищает от его поломки. Дампы содержат данные аккаунтов.

Для проверки восстановления создайте отдельную пустую базу `memly_restore_test`
в pgAdmin. В PowerShell (замените пользователя, версию PostgreSQL и имя файла):

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_restore.exe' --host=localhost --port=5432 --username=postgres --dbname=memly_restore_test --no-owner --no-acl --exit-on-error --password '.\backups\ИМЯ_КОПИИ.dump'
```

Пароль вводится по запросу. Не восстанавливайте тестовую копию поверх рабочей базы.
В pgAdmin проверьте наличие таблиц, аккаунтов и наборов в тестовой базе.

## Типичные ошибки

- `Источник запроса не разрешён`: проверьте точное совпадение адреса с
  `TRUSTED_ORIGINS`, без завершающего `/`, и перезапустите сервер.
- `Production требует HTTPS и SMTP`: проверьте настройки `.env`.
- `Сначала выполните npm run build`: сборка клиента отсутствует в корневом `dist`.
- ngrok показывает недоступный upstream: проверьте, что `npm start` работает и PORT совпадает.
- Ошибка подтверждения почты: проверьте пароль приложения, SMTP_FROM и папку спам.
  Проверка наличия SMTP-полей при запуске не доказывает успешную отправку письма.
- База недоступна: проверьте службу PostgreSQL и DATABASE_URL.
- После перезапуска системы сайт недоступен: запустите оба процесса снова.
