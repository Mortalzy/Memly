# Архитектура Memly

Актуально на 9 октября 2026 года. Бесплатное веб-приложение без AI. Реализованы
серверная библиотека и учебные сессии всех четырёх режимов.

## Стек

| Область          | Реализация                                                           |
| ---------------- | -------------------------------------------------------------------- |
| Runtime / язык   | Node.js 24, npm 11, TypeScript strict                                |
| Клиент           | React 19, Vite, CSS выбранного прототипа, hash-маршруты              |
| Серверные данные | TanStack Query; данные аккаунта не сохраняются в localStorage        |
| API              | Express 5, REST `/api/v1`, валидация Zod                             |
| Авторизация      | Better Auth, Prisma-адаптер, email/password, серверные cookie-сессии |
| База             | PostgreSQL 18, Prisma 7.10, `@prisma/adapter-pg`                     |
| Миграции         | Prisma Migrate и проверяемые SQL-файлы                               |
| Почта            | Nodemailer / SMTP; включается конфигурацией                          |
| Логи             | Pino, генерируемый request ID, статус и время ответа                 |
| Проверки         | TypeScript, Prettier, Node test, Supertest, RTL/JSDOM                |
| CI               | GitHub Actions, PostgreSQL 18, локальный тестовый SMTP               |

Patch-версии фиксируются в package.json и package-lock.json. Prisma 8 RC не используется.
Prisma заменяет первоначальный Drizzle: см. [ADR 0004](adr/0004-backend-foundation.md).
Технологии будущих этапов подключаются по необходимости, а не как пустые зависимости.

## Границы

Клиент отправляет JSON и получает DTO из `packages/contracts`. Он не импортирует модели
или подключение базы. HTTP-маршруты проверяют вход и вызывают сервисы. Сервисы проверяют
владение/доступ и выполняют транзакции через `packages/database`. Auth монтируется до
JSON-парсера, поскольку Better Auth самостоятельно читает поток запроса.

В development Vite проксирует `/api` к Express. Для production нужен единый HTTPS-origin:
reverse proxy обслуживает `dist` и направляет `/api` к API. PostgreSQL недоступен браузеру.
Этот Express/PostgreSQL backend предназначен для обычного Node-хостинга; опубликованный
статический дизайн-прототип отдельно и не подменяет полнофункциональное приложение.

## Модель и конкурентные изменения

- Better Auth: users, sessions, accounts, verifications и rate_limits. Пароль хранится
  как хеш; auth-данные никогда не включаются в прикладной DTO.
- Deck принадлежит пользователю. Видимость private/public, приватная по умолчанию.
- Готовая подборка английского — read-only каталог в API. Добавление создаёт личный private Deck с новыми карточками/версиями. Уникальность ownerId/starterKey предотвращает дубликаты; обновления каталога не перезаписывают личные копии. См. [ADR 0006](adr/0006-starter-decks.md).
- Card имеет стабильный UUID, позицию и ревизию. Каждая правка текста создаёт CardVersion.
  Добавление/удаление/порядок карточек и метаданные набора сохраняются одной транзакцией.
- PUT/DELETE набора требуют текущую ревизию. Устаревшая запись получает 409 без потери
  новых данных. Нельзя присвоить чужую карточку или чужую папку.
- В первом этапе набор имеет одну папку своего владельца. Удаление папки отвязывает
  наборы. Многие-ко-многим, теги и unlisted-ссылки — будущие изменения модели.
- Favorite относится к пользователю и набору. Личная библиотека включает свои наборы
  и доступные публичные наборы из избранного. Скрытый автором набор исчезает у других.
- CardProgress — личная самооценка для текущей версии карточки. Изменённый текст требует
  повторной отметки: прогресс прежней версии не учитывается. Оценки учебных режимов также обновляют текущий прогресс; FSRS ещё не реализован.
- ReviewEvent имеет уникальность user/eventId, серверное время и параметры действия.
  Повтор той же доставки не увеличивает число повторений. ID с другим содержимым — 409.
  История самооценок сохраняется после удаления карточки; активный прогресс удаляется с ней.

Запись наборов, привязка папок, избранное и самооценки проверяются в транзакциях;
для операций с зависимыми правами используется Serializable. Конфликт БД возвращается
как 409. Учебные сессии хранят собственный снимок, очередь и черновик; `@memly/study-engine`
проверяет действия. Запуск/действия имеют ID идемпотентности и ревизию. Ответы теста
скрыты до сдачи, результаты вычисляются сервером. Прогресс переносится только на
неизменённые версии карточек. История сессий и личные рекорды доступны владельцу.
См. [ADR 0005](adr/0005-study-sessions.md) для правил режимов, удаления и ограничений.

## Доступ и эксплуатация

Чужой private-набор и чужие папки возвращают 404. Публичный набор доступен любому
вошедшему пользователю, но редактируется только владельцем. Публичный DTO скрывает папку
владельца и отражает избранное/прогресс текущего пользователя.

Cookie HttpOnly, SameSite=Lax, Secure в production; cookie-cache отключён, поэтому
отозванная сессия сразу перестаёт работать. Мутации требуют JSON и точный Origin из
TRUSTED_ORIGINS. CORS с wildcard отсутствует. IP для auth выводится из Express req.ip
и не принимается из произвольного клиентского заголовка. TRUST_PROXY=1 допустим только
за одним доверенным reverse proxy, который контролирует forwarded-заголовки.

Helmet, лимиты тела/полей/карточек и rate limiting включены. Auth-лимиты хранятся в БД;
общий HTTP-лимит пока локален процессу. При нескольких экземплярах API потребуется
распределённый store общего лимитера. В журнал не записываются пароли, cookies,
учебный текст, строки подключения или полный SQL error.

Health `/api/health` проверяет процесс, ready `/api/ready` — доступность БД. При остановке
сервер перестаёт принимать соединения, ждёт текущие запросы и отключает БД. Production
требует отдельной настройки хостинга, HTTPS, SMTP и резервных копий.
