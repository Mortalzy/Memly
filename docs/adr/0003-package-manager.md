# ADR-0003: переход на npm

- Статус: принято.
- Дата: 7 октября 2026 года.
- Заменяет выбор pnpm в ADR-0001.

## Контекст

Пользователю привычнее работать с npm. Проект содержит фронтенд-прототип и заготовки
других приложений и пакетов; отдельные возможности pnpm ему пока не нужны.

## Решение

Используем npm 11 вместе с Node.js 24. Workspaces `apps/*` и `packages/*` объявлены
в корневом `package.json`. Общие команды запускают сценарии `@memly/web` через
`npm run <script> --workspace=@memly/web`. В репозитории хранится `package-lock.json`.
Конфигурация и lock-файл прежнего менеджера пакетов удалены.

Для установки точных версий из репозитория используется `npm ci`.
При добавлении или обновлении зависимости используется `npm install`, например
`npm install <package> --workspace=@memly/web`; изменённый lock-файл коммитится.

## Последствия

Corepack и отдельная установка pnpm больше не требуются. Структура монорепозитория
сохраняется; новые приложения подключаются как npm workspaces по мере появления
их `package.json`. Прямые зависимости фронтенда сохраняют зафиксированные версии.

`esbuild` 0.28.2 явно указан как инструмент разработки фронтенда: это удовлетворяет
опциональную peer-зависимость Vite 8 и предотвращает некорректные записи о платформенных
пакетах в npm lock-файле. `tsx` использует свою совместимую версию esbuild.

Проверки миграции: чистая установка `npm ci`, проверка типов, форматирования,
существующих тестов поведения и production-сборки через npm.
