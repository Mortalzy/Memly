# ADR-0001: фундамент Memly

Дата: 2026-10-06.

Статус: принято для начального плана. Бизнес-модель, мобильные клиенты и внешние провайдеры остаются продуктовыми решениями.

## Контекст

Пользователь выбрал React, Express и PostgreSQL как ориентир и запросил план аналога Quizlet с карточками, играми и остальными основными возможностями. Требуются качественная архитектура, последовательное развитие и единый стиль кода. Репозиторий изначально пуст.

## Решение

1. Сохранить React + Express + PostgreSQL и использовать TypeScript во всех приложениях и общих пакетах.
2. Создать монорепозиторий pnpm с web/api и отложенным worker. Общие пакеты: contracts, study-engine, database, ui.
3. API реализовать как модульный монолит. Модули разделяют ответственность, но не требуют отдельных сетевых сервисов.
4. Использовать Drizzle ORM + `pg`, Better Auth с Drizzle-адаптером и серверными сессиями.
5. Отделить карточки и версии контента от личного прогресса, сессий и журналов повторений.
6. Для долгосрочных повторений использовать FSRS через `ts-fsrs`; адаптивность Learn реализовать отдельно.
7. Начать с E1–E2. Redis, Socket.IO, объектное хранилище и AI добавлять на этапах, которые их используют.
8. Закрепить два пробела, UTF-8, LF и автоматическое форматирование.

## Причины

Общие контракты уменьшают риск расхождения клиента и сервера. PostgreSQL подходит для связанных сущностей, ограничений, транзакций и первоначального поиска. Явные модули позволяют сначала реализовать индивидуальное обучение, затем подключить группы, игры и AI без второго набора бизнес-правил.

Drizzle сохраняет типизацию и возможность явного SQL для поиска и аналитики. Готовая auth-библиотека управляет сессиями и восстановлением доступа. Чистый учебный движок упрощает проверку алгоритмов и повторное использование в будущих клиентах.

## Последствия

Рабочий каркас требует настройки нескольких пакетов и общих команд. Версии Better Auth, его адаптера и Drizzle нужно проверять совместно. Веб-приложение не заменяет автоматически нативные клиенты. Полный продукт включает операционные и контентные работы помимо программирования.

После появления реальной нагрузки можно масштабировать API, worker и хранилища независимо. Выделение отдельного микросервиса допустимо при конкретной измеренной необходимости; оно не является требованием исходного плана.

## Текущее исполнение

На E0 созданы только документация, метаданные монорепозитория, каталоги с описаниями и настройки стиля. Прикладной код, зависимости и инфраструктура будут созданы на следующем этапе.
