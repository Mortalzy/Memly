# ADR 0004 — Первый серверный этап, Prisma и серверные сессии

Дата: 8 октября 2026 года. Статус: принято пользователем в плане реализации сервера.
Дополняет ADR 0001 и заменяет первоначальный выбор Drizzle для доступа к БД.

## Решение

Сохраняем React/Express/TypeScript/PostgreSQL и npm workspaces. Используем Prisma 7
с официальным PostgreSQL-адаптером и Better Auth с Prisma-адаптером. Prisma 8 RC не
подключаем. Общие DTO и схемы входа находятся в contracts; ORM-модели — только на сервере.

Объём первого этапа: авторизация, профиль, наборы и карточки, папки, избранное, видимость,
поиск и сохранение самооценки. Учебные тесты, игры, FSRS и long-lived sessions идут
следующим этапом. Приложение бесплатное, AI и биллинг исключены из текущего плана.

Cookie-сессии вместо клиентских bearer-токенов. Один origin, JSON и trusted Origin для
мутаций, БД хранит auth rate limits. Сессия проверяется в БД, без cookie-cache.
SMTP включает подтверждение почты и восстановление; в production почта обязательна.

Один набор относится к одной папке своего владельца. Private/public; unlisted и
многие-ко-многим добавятся позже отдельной миграцией. Редактор сохраняет весь набор
атомарно и передаёт ревизию. При изменении карточки сохраняется её версия, а прогресс
старого содержания не учитывается до повторной отметки.

## Последствия

Нужны PostgreSQL и переменные окружения: standalone фронтенд больше не является
основным запуском приложения. Деморежим остаётся явным через VITE_DEMO_MODE и не
включается автоматически при ошибке API. SQL-миграции коммитятся, generated client — нет.

Node 24 запускает TS-источники общих пакетов с native type stripping; API компилируется
в JS, в development используется tsx. Общие пакеты используют только стираемый TS-синтаксис.
При публикации пакетов отдельно потребуется отдельный JS-build и exports.

Уязвимые транзитивные deepmerge-ts/mysql2 закрепляются на исправленных версиях через
npm overrides; совместимость проверяется конфигурацией Prisma, миграциями и сборкой.
