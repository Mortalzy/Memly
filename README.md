# Memly

Бесплатное веб-приложение для обучения по карточкам. React + TypeScript, Express 5,
PostgreSQL 18, Prisma 7, Better Auth и npm workspaces. AI-функции не входят в проект.

## Что работает

- Регистрация, вход, серверные сессии, выход с отзывом сессии и изменение имени профиля.
- Создание, чтение, редактирование и удаление наборов и карточек.
- Приватные по умолчанию и публичные наборы, каталог, поиск, личное избранное.
- Подборка «Наборы Memly»: 10 готовых наборов английского по 40 карточек с предпросмотром и добавлением редактируемой личной копии.
- Папки; удаление папки сохраняет её наборы.
- Карточки: переворот, навигация, самооценка и завершение после всех выбранных карточек.
- Заучивание: выбор/письменный ответ, повтор ошибок, две ступени в смешанном режиме.
- Тест: автоматическое сохранение черновика, серверная оценка и разбор после сдачи.
- Подбор: все выбранные карточки раундами до 6 пар, ошибки, время и личный рекорд.
- Настройки направления, количества, порядка и фильтра «Ещё не знаю»; повтор сложных карточек.
- Восстановление незавершённых занятий, история и статистика за 7/30 дней.
- Массовое добавление карточек из строк с предпросмотром.
- Версии карточек, защита от перезаписи параллельных правок, проверка прав на сервере.
- При настройке SMTP: подтверждение почты и восстановление пароля с отзывом старых сессий.

Все четыре режима работают с сервером. Письменные ответы сравниваются без учёта регистра
и лишних пробелов; смысл и синонимы не проверяются. FSRS, медиа, offline и совместные игры
ещё не реализованы. SMTP и production-хостинг настраиваются отдельно.

При обновлении существующего проекта остановите dev-сервер и выполните:

```bash
git pull
npm ci
npm run db:generate
npm run db:migrate
npm run dev
```

Миграции добавляют учебные сессии и связь личных копий с готовой подборкой; существующие аккаунты и наборы сохраняются.

## Запуск в VS Code

Нужны Node.js 24, npm 11 и PostgreSQL 18 (локальный или Docker Desktop).

1. Установите зависимости:

   ```bash
   npm ci
   ```

2. Скопируйте `.env.example` в `.env` в корне. В PowerShell: `Copy-Item .env.example .env`;
   в bash: `cp .env.example .env`.
3. Сгенерируйте секрет и вставьте результат в `BETTER_AUTH_SECRET`:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

4. Запустите PostgreSQL. Для Docker:

   ```bash
   docker compose up -d --wait
   ```

   Compose создаёт базу `memly`, пользователя `memly` и пароль `memly` только для локальной
   разработки. При своей БД укажите её строку подключения в `DATABASE_URL`.

5. Подготовьте клиент БД и примените миграции:

   ```bash
   npm run db:generate
   npm run db:migrate
   ```

6. Запустите клиент и сервер:

   ```bash
   npm run dev
   ```

Откройте **http://localhost:5173** и зарегистрируйтесь. Создайте свой набор или откройте
«Моя библиотека → Наборы Memly», посмотрите карточки и добавьте нужную тему.
Подборка доступна сразу после миграций, отдельный seed не нужен. API работает на порту 3001; Vite проксирует `/api`, поэтому браузер
работает с одним origin. При другом адресе клиента измените `BETTER_AUTH_URL` и
`TRUSTED_ORIGINS`. Порт Vite фиксирован: при занятом 5173 процесс завершится с ошибкой.

Отдельно: `npm run dev:api` и `npm run dev:web`. После `npm run build` сервер запускается
через `npm run start:api`; статический клиент из `dist` должен обслуживаться вместе с
`/api` через один origin. `npm run preview` показывает только сборку фронтенда, без API.

## SMTP

Без SMTP в development доступна регистрация без подтверждения почты; восстановление
пароля скрыто. Для email-сценариев задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` и при
необходимости `SMTP_USER` / `SMTP_PASSWORD`. Не включайте учётные данные в git.

С настроенным SMTP новый пользователь сначала подтверждает почту по письму. Вход
неподтверждённого пользователя повторно отправляет ссылку. В production требуются SMTP,
HTTPS, сильный секрет и точные trusted origins. Порт 465 использует TLS, другие порты в
production требуют STARTTLS. Для Gmail обычно нужен пароль приложения.

## Проверки

```bash
npm run typecheck
npm run format:check
npm test
npm run build
```

API-тесты требуют отдельную базу **memly_test**. Они не запускаются без `TEST_DATABASE_URL`
и явно отмечаются как пропущенные. Не указывайте пользовательскую базу.

В bash, после создания тестовой БД:

```bash
DATABASE_URL=postgresql://memly:password@localhost:5432/memly_test npm run db:migrate
TEST_DATABASE_URL=postgresql://memly:password@localhost:5432/memly_test npm test
```

В PowerShell задайте соответствующую переменную через `$env:DATABASE_URL = '...'` перед
миграцией и `$env:TEST_DATABASE_URL = '...'` перед тестами. GitHub Actions сам запускает
PostgreSQL 18, применяет миграции и выполняет API- и UI-тесты, типы, форматирование и сборку.
Почтовые тесты используют локальный SMTP-приёмник, без отправки реальным людям.
